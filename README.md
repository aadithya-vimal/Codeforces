## 🧭 The repository

This is my personal collection of **Codeforces solutions**, organised by problem rating.

The goal is simple: keep a readable, searchable record of what I've solved, track my progress, and have a place to revisit problems when future me inevitably forgets a clever trick.

No generated solution dumps. No mystery folders. Just the problems, the code, and the learning curve.

## 🗂️ Repository structure

```text
Codeforces/
├── README.md
└── solutions/
    └── 800/
        ├── 4A-watermelon.cpp
        ├── 71A-way-too-long-words.cpp
        ├── 231A-team.java
        └── ...
```

Each solution is stored under its Codeforces problem rating.

**Filename convention**

`<problem-id>-<problem-name>.<extension>`

For example: `4A-watermelon.cpp`

The problem ID makes files easy to locate; the title makes them human-readable. A rare case of both worlds getting along.

## 🧩 Languages

| Language | Extensions |

Solutions are kept in the language in which they were accepted. I may use different languages depending on the problem and what I want to practise.

## 🧠 How I use this archive

- Solve a problem on [Codeforces](https://codeforces.com/profile/aadithyavimal).
- Keep the accepted implementation.
- Place it in the corresponding rating directory.
- Give it a consistent, descriptive filename.
- Commit it so the repository history records the journey.

The commit history is intentionally granular: **each problem gets its own commit**. Small steps make a rather useful trail.

## 🔎 Finding a solution

Browse by rating in [`solutions/`](./solutions/), or use GitHub's file search to look up a problem ID or title.

You can also jump straight to a problem by replacing the ID in:

`https://codeforces.com/problemset/problem/<contestId>/<index>`

## 🌱 Progress

This repository is a work in progress. The current collection is mostly in the **800-rated** range; the plan is to keep adding accepted solutions as I move through harder problems.

The long-term objective isn't to collect files for the sake of collecting files. It's to build a useful record of improved problem-solving: better complexity analysis, cleaner implementations, stronger data-structure intuition, and fewer bugs that only appear on test 37.

## ⚖️ A small note

These are personal practice solutions, shared for learning and reference. If you're working on the same problems, give them a try yourself before looking at an implementation — the satisfaction is worth it.
